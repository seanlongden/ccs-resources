**The main finding**

There is substantial useful material here. What is missing is a reliable connection between:

**What the student learns → what they give their AI → what the AI produces → what someone checks → what happens next.**

A few examples show why this matters:

- The launch runbook references skill names that differ from the supplied skills pack.
- The existing installation teaches Claude Code, while the new documents specify Grok Bot.
- Some instructions describe two follow-ups; others describe three.
- The new scraping document contains a code skeleton, with essential parts left to be built.
- The handover documents sometimes tell students to install skills that should already have been installed before launch.
- Some existing resources point to templates “in Notion” without providing the actual file.

The plan needs to resolve those gaps as well as improve the teaching and presentation.

**9. The worked example**

One complete example should run through Install, Resources and Training. Students should see the same business, files and decisions throughout.

**Illustrative training case: an existing agency selling cold-email services to industrial maintenance companies. All figures below are examples.**

| Stage | Example input and finished output |
|---|---|
| **Business brief** | The agency can deliver cold email. It chooses maintenance companies with spare capacity and customers worth around $60,000 in first-year revenue. These become entries in `profile.md`. |
| **Buyer selection** | Agency acquisition targets maintenance-company owners or sales leaders. Their clients’ delivery campaigns target relevant manufacturing buyers, such as plant managers. Separate profiles and qualification rules are created. |
| **Offer** | Example engagement: ten agreed qualified opportunities over 90 days for $6,000, with $3,000 to start and $3,000 after five accepted opportunities. An opportunity has a written definition agreed with the client. |
| **Buyer economics** | If two opportunities eventually become $60,000 accounts, that is $120,000 in first-year revenue against a $6,000 agency fee. It is a conditional revenue comparison, not profit or cash collected that quarter. |
| **Research** | `research-brief.md` contains real sources, buyer language, exclusions and proposed angles. Unsupported claims are marked for review. |
| **Leads** | A saved search, raw list, cleaned list, 50-company calibration sample and qualified list show exactly how a company passes or fails. |
| **Copy** | `copy-locked.md` contains approved emails, the exact variables used and rendered examples. Every claim matches the approved offer and proof. |
| **Campaign** | The correct leads, copy, inboxes and settings appear in a paused campaign. Counts and previews match the approved files. |
| **Reply and booking** | A controlled test reply produces a research summary, fit decision and draft with genuinely available times. Approval leads to the correct booking and stops further campaign emails. |
| **Weekly operation** | The report shows sends, interested replies, booked meetings, lead runway and any health issues. The student can identify the next action. |
| **Handover** | The completed handover pack identifies the live setup, verified results, active routines, outstanding issues and what the student does next week. |

The case should also demonstrate failure: a missing website, a bad-fit reply, a changed calendar slot, an expired connection and a campaign running out of leads.

The eventual teaching example can use an approved anonymised real case where available. Any simulated data remains clearly labelled.

**10. Technical and visual acceptance checks**

The technical test must establish that:

- Skills install correctly and the expected files and connections are available.
- Required input is requested instead of guessed.
- Lead rows, exclusions, duplicates and held records reconcile.
- Qualification is checked against a human-labelled sample.
- Email variables render correctly.
- Campaigns remain paused until approved.
- A reply event is handled once, including after an interrupted run.
- Changed threads, opt-outs and booked leads stop inappropriate follow-ups.
- Calendar conflicts and time zones are handled correctly.
- Missing access, API errors and cost limits produce a useful stop message.
- Refills and reporting work without rebuilding the system manually.

Any delivery test using email or messages must use controlled accounts and approved copy. A prospect is never used as a transport test.

For the portal, I would inspect every new or materially changed page on desktop and phone. Checks include readable spacing, tables, code blocks, copy buttons, downloads, breadcrumbs, next steps and working links. AI instructions must be clearly separated from the explanation students read.

Finally, a supervised walkthrough should check whether someone new to the setup can complete the steps without an unstated explanation from us.
